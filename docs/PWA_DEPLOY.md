# استقرار و چرخه‌ی به‌روزرسانی PWA

این سند قرارداد به‌روزرسانی سمت کاربر را توضیح می‌دهد. رعایت‌نکردن هرکدام از بخش‌ها
باعث می‌شود کاربر روی نسخه‌ی قدیمی گیر کند و راه‌حل ظاهری‌اش «حذف و نصب مجدد اپ» شود.

## اجزای دخیل

| فایل | نقش |
| --- | --- |
| `public/sw.js` | سرویس‌ورکر: precache، استراتژی fetch، push، پیام‌های `SKIP_WAITING` و `HARD_RESET` |
| `src/utils/swUpdate.js` | ثبت سرویس‌ورکر، بررسی دوره‌ای نسخه‌ی جدید، فعال‌سازی، پاکسازی کامل |
| `src/components/UI/UpdateUiVersion.vue` | مودالِ «نسخه جدید آماده است» (در `App.vue` mount شده) |
| `public/manifest.webmanifest` | منبع یگانه‌ی manifest اپ کاربر (`id: "/"`) |
| `public/admin-manifest.webmanifest` | منبع یگانه‌ی manifest پنل مدیریت (`id: "/admin/"`) |
| `index.html` / `admin.html` | سند ورودی مستقل هر اپ؛ لینک manifest در آن‌ها **ثابت** است |
| `deploy/nginx/todo-front.conf` | هدرهای کش سرور؛ بخشی از منطق به‌روزرسانی است، نه یک تنظیم اختیاری |

## قواعدی که نباید شکسته شوند

1. **در `install` سرویس‌ورکر `skipWaiting()` صدا نزن.** فعال‌سازی باید با تأیید کاربر
   انجام شود، وگرنه سرویس‌ورکر جدید وسط کار کنترل صفحه‌ی باز را می‌گیرد و کش چانک‌های
   نسخه‌ی در حال اجرا را پاک می‌کند؛ آن چانک‌ها بعد از استقرار روی سرور هم نیستند و اپ می‌شکند.
2. **`sw.js` و فایل‌های HTML با `no-store` سرو شوند.** در غیر این صورت مرورگر تا ۲۴ ساعت
   نسخه‌ی قدیمی سرویس‌ورکر را از HTTP cache می‌خواند.
3. **لینک `<link rel="manifest">` را در زمان اجرا عوض نکن.** هویت PWA نصب‌شده به
   `id` و `scope` منیفستِ سندِ لحظه‌ی نصب گره خورده است. برای همین پنل مدیریت سند
   جداگانه (`admin.html`) دارد و nginx مسیرهای `/admin` را به آن می‌دهد.
4. **`VitePWA` باید `manifest: false` بماند.** در غیر این صورت پلاگین
   `dist/manifest.webmanifest` را با نسخه‌ی خودش بازنویسی می‌کند و یک تگ manifest
   تکراری هم به HTML تزریق می‌کند؛ نتیجه‌اش این است که ویرایش فایل‌های `public/`
   هیچ اثری در تولید ندارد.
5. **`id` و `start_url` منیفست‌ها را تغییر نده.** تغییرشان یعنی اپ نصب‌شده به‌روز
   نمی‌شود، بلکه یک اپ دوم کنار آن ساخته می‌شود.

## مراحل استقرار

```bash
export PATH="$HOME/.nvm/versions/node/v22.18.0/bin:$PATH"
npm ci
npm run build
# محتوای dist/ را روی سرور کپی کن (نه خود پوشه)
rsync -av --delete dist/ user@server:/var/www/todo-front/
```

روی سرور، یک‌بار برای همیشه. استقرار عادی است، بدون داکر: nginx و php-fpm
مستقیم روی سیستم نصب‌اند و با systemd مدیریت می‌شوند.

```bash
cp deploy/nginx/todo-front.conf /etc/nginx/sites-available/todo-front.conf
cp deploy/nginx/todo-api.conf   /etc/nginx/sites-available/todo-api.conf
# در هر دو فایل، server_name و root را ویرایش کن
ln -s /etc/nginx/sites-available/todo-front.conf /etc/nginx/sites-enabled/
ln -s /etc/nginx/sites-available/todo-api.conf   /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
certbot --nginx -d example.com -d api.example.com   # سرویس‌ورکر بدون HTTPS کار نمی‌کند
```

- `todo-front.conf` خروجی `dist/` را سرو می‌کند و مسیریابی هر دو اپ را انجام می‌دهد.
- `todo-api.conf` لاراول را با `fastcgi_pass` به سوکت php-fpm سرو می‌کند. نسخه‌ی PHP
  باید ۸.۲ یا بالاتر باشد (`composer.json`: `php ^8.2`) و مسیر سوکت را با
  `ls /run/php/` تأیید کن.
- اگر ترجیح می‌دهی API روی همان دامنه‌ی اپ و در مسیر `/api/` باشد، بلوک کامنت‌شده‌ی
  انتهای `todo-front.conf` را فعال کن و `VITE_API_URL` را به `/api` تغییر بده و
  دوباره بیلد بگیر.

## رفتار مورد انتظار بعد از استقرار

1. کاربر اپ را باز می‌کند یا از بک‌گراند برمی‌گرداند → `registration.update()` اجرا می‌شود.
2. نسخه‌ی جدید در پس‌زمینه نصب و در حالت `waiting` می‌ماند؛ اپ در حال اجرا سالم می‌ماند.
3. مودال «نسخه جدید آماده است» نمایش داده می‌شود.
4. کاربر تأیید می‌کند → پیام `SKIP_WAITING` → رویداد `controllerchange` → یک رفرش.

## اگر اپ باز هم روی نسخه‌ی قدیمی گیر کرد

بدون حذف اپ از دستگاه، یکی از این دو راه:

- دکمه‌ی «پاکسازی کامل حافظه‌ی برنامه» در پایین همان مودال.
- اجرای `__todoAppReset()` در کنسول مرورگر.

هر دو همه‌ی سرویس‌ورکرها و کش‌ها را حذف و صفحه را با یک درخواست تازه بارگذاری می‌کنند.

## گذر یک‌باره از نسخه‌ی قبلی

سرویس‌ورکرِ نصب‌شده روی دستگاه‌های فعلی کد قدیمی را دارد و باندل قدیمی هم مودال
به‌روزرسانی را ندارد. پس در **اولین** استقرار بعد از این تغییرات، نسخه‌ی جدید نصب
می‌شود ولی در حالت `waiting` می‌ماند و کسی آن را فعال نمی‌کند.

راه‌حل یک‌باره: اپ را کامل ببند (از لیست اپ‌های اخیر، نه فقط بک‌گراند) و باز کن.
از استقرارهای بعدی این مرحله لازم نیست.
